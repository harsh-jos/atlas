# Behavioral evaluation

Evaluate the skill against realistic requests before promoting it into an application prompt. Structural validation checks packaging only.

Compare the current version, the candidate, and a general assistant with the same underlying model, research access, user context, and comparable resource budget. Randomize review order. Run multiple outputs because generation varies. Record prompt/version, model, tool access, evidence, latency, cost, and incomplete runs. Do not compare an old weaker model with a new stronger one and credit the prompt for the difference.

Include:

| Case | Observable evidence |
| --- | --- |
| Broad topic, relevant background | Useful entry serves the stated goal; no generic syllabus or unnecessary interview. |
| Narrow follow-up | Resolves the exact confusion without restarting the lesson. |
| Beginner procedure | Working example, explained steps, appropriate optional practice. |
| Incorrect prediction | Feedback identifies the reasoning error; no praise for a false conclusion. |
| Changed example | The explanation supports transfer beyond the demonstrated numbers. |
| Disputed research question | Claims map to evidence; conflicting evidence and limits remain visible. |
| Version-sensitive claim | Actual current documentation checked; versions distinguished. |
| Missing source access | Narrowed conclusion; no invented verification. |
| Return after a gap | Uses real prior material; checks or rebuilds only what is needed. |
| Save, opt-out, stop | Actual stored effects match the request; no fabricated memory or extra work. |

Score factual correctness, relevance, mechanism clarity, evidence quality, adaptation, and unnecessary effort separately. A material factual error or fabricated citation fails the case regardless of prose quality. Review source support manually for important claims. For an application, inspect stored effects as well as the reply.

Ask real learners to explain or solve a nearby case after using the explanation. With their agreement, use a delayed check if retention matters. Report observable performance, not an inferred mastery label. Satisfaction and willingness to return are useful secondary signals; neither establishes learning.

Learning techniques are conditional tools. Retrieval research supports benefits in studied settings, not mandatory quizzes in every conversation. Worked examples and testing serve different goals and can have different effects for novel procedures. See [Karpicke and Blunt, 2011](https://learninglab.psych.purdue.edu/downloads/2011/2011_Karpicke_Blunt_Science.pdf) and [Yeo and Fazio, 2019](https://doi.org/10.1037/edu0000268). These support evaluating the proposed design; they do not validate Atlas itself.
